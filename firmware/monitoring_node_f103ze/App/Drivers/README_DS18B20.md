## 下一步操作

### CubeMX 配置
由于 DS18B20 使用软件位操作实现 1-Wire，**不需要在 CubeMX 中配置外设**，但需要确认 GPIO 引脚已启用：

1. 打开 `monitoring_node_f103ze.ioc`
2. 找到 **PG9** 引脚
3. 设置为 **GPIO_Output** 或保持默认（驱动中会动态切换输入/输出）
4. 保存并重新生成代码

### 硬件连接
```
DS18B20           STM32F103ZET6
--------          --------------
DQ    ----------- PG9 + 4.7kΩ 上拉到 3.3V
VDD   ----------- 3.3V
GND   ----------- GND
```

⚠️ **上拉电阻必须接**：1-Wire 协议需要上拉电阻将总线保持在高电平。

### 编译和烧录
1. 在 CubeIDE 中打开项目
2. 将驱动文件添加到项目中（如果 IDE 未自动识别）
3. 编译项目（可能需要调整微秒延时函数）
4. 烧录到开发板
5. 通过串口查看测试输出（115200 bps）

## 已知问题

### 微秒延时函数
`ds18b20.c` 中的 `DS18B20_DelayUs()` 使用简单循环实现，需要根据实际主频校准。推荐方案：

**方法 1：启用 DWT 计数器**（精确）
在 `main.c` 的 `SystemClock_Config()` 后添加：
```c
CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;
DWT->CYCCNT = 0;
DWT->CTRL |= DWT_CTRL_CYCCNTENA_Msk;
```

然后在 `ds18b20.c` 中启用 DWT 方法（取消注释）。

**方法 2：使用 SysTick**
如果 DWT 不可用，保持当前循环延时，但需要用逻辑分析仪验证时序。

## 调试建议
1. 先运行**测试 1**（器件检测），确认硬件连接正常
2. 如果检测失败，用万用表检查：
   - PG9 是否有 3.3V（上拉电阻）
   - VDD 是否为 3.3V
   - GND 是否连接
3. 如果 CRC 频繁失败，调整延时函数
4. 用逻辑分析仪捕获 1-Wire 波形，对比数据手册时序
