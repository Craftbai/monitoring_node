# M1.2 - RTC 周期唤醒验证

## 验证目标

配置 RTC Alarm 实现 5 秒周期唤醒，验证：
1. RTC 时钟正常运行
2. RTC Alarm 中断能正确触发
3. 能在主循环处理 Alarm 事件并重新设置下一次唤醒
4. 实现持续的周期唤醒机制

## 硬件配置

- **MCU**: STM32F103ZET6
- **开发板**: 正点原子精英 V2
- **RTC 时钟源**: LSE（外部 32.768 kHz 晶振）
- **指示灯**: LED0（STATUS_LED，PB5）

## 软件配置

### CubeMX 配置

**RTC 模式**：
- Activate Clock Source: ✓
- Activate Calendar: ✓
- RTC OUT: Disable
- Clock Configuration: LSE → RTC Clock

**初始时间**：
- Hours: 0x00
- Minutes: 0x00  
- Seconds: 0x10（BCD 格式，即 10 秒）

**NVIC 配置**：
- RTC alarm interrupt through EXTI line: ✓ Enabled
- Preemption Priority: **15**（最低优先级，避免阻塞 SysTick）
- Sub Priority: 0

### 代码实现

**关键修复点**：
1. **中断优先级问题**：RTC Alarm 中断优先级必须低于 SysTick（默认 15），否则 `HAL_Delay()` 会死锁
2. **中断回调限制**：不能在 `HAL_RTC_AlarmAEventCallback()` 中使用 `HAL_Delay()`，只设置标志
3. **BCD 格式处理**：STM32F1 的 RTC 时间使用 BCD 格式，需要正确转换

**实现逻辑**：
```c
// 全局变量
static volatile uint8_t alarm_triggered = 0;
static uint32_t wakeup_count = 0;

// RTC Alarm 中断回调（在中断上下文）
void HAL_RTC_AlarmAEventCallback(RTC_HandleTypeDef *hrtc)
{
  wakeup_count++;
  alarm_triggered = 1;  // 只设置标志
}

// 主循环处理
while (1)
{
  if (alarm_triggered)
  {
    alarm_triggered = 0;
    
    // LED 快闪 3 次表示唤醒
    for (int i = 0; i < 3; i++) { ... }
    
    // 重新设置下一次 5 秒唤醒
    RTC_TimeTypeDef sTime;
    HAL_RTC_GetTime(&hrtc, &sTime, RTC_FORMAT_BCD);
    
    // BCD 转十进制 → 加 5 秒 → 转回 BCD
    uint8_t current_sec = BCD_TO_DEC(sTime.Seconds);
    uint8_t next_sec = (current_sec + 5) % 60;
    
    RTC_AlarmTypeDef sAlarm;
    sAlarm.AlarmTime.Seconds = DEC_TO_BCD(next_sec);
    HAL_RTC_SetAlarm_IT(&hrtc, &sAlarm, RTC_FORMAT_BCD);
  }
  
  // LED 心跳
  HAL_GPIO_TogglePin(STATUS_LED_GPIO_Port, STATUS_LED_Pin);
  HAL_Delay(1000);
}
```

## 验证结果

### 观察现象

✅ **LED 行为符合预期**：
- 启动后 LED 以 1Hz 频率慢闪（心跳）
- 约 5 秒后，LED 快速闪烁 3 次（100ms 间隔）
- 继续慢闪约 3-4 次
- 再次快闪 3 次
- **持续周期性循环**

### 时序分析

- **心跳周期**: 1000ms（慢闪）
- **唤醒指示**: 3 次快闪，每次 200ms（100ms 亮 + 100ms 灭）= 600ms
- **RTC Alarm 周期**: 5 秒
- **实际观察**: 慢闪约 3-4 次后快闪，符合 (5000ms - 600ms) / 1000ms ≈ 4.4 次

### 关键问题与解决

**问题 1**: 程序下载后 LED 闪烁 6 次就停止
- **原因**: 在 RTC Alarm 中断回调中使用了 `HAL_Delay()`，导致死锁
- **解决**: 中断回调只设置标志，在主循环处理

**问题 2**: 程序跳到 Bootloader 区域（0x1ffff3b6）
- **原因**: RTC Alarm 中断优先级设置为 0（最高），阻塞了 SysTick 中断
- **解决**: 将 RTC Alarm 中断优先级设置为 15（最低）

**问题 3**: `HAL_Delay()` 在调试时卡死
- **原因**: RTC 中断优先级高于或等于 SysTick，导致 SysTick 计数无法更新
- **解决**: 参考 ST 社区和网上例程，使用最低优先级 15
