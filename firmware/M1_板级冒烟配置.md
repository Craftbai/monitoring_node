# M1 板级冒烟配置

本文档用于 STM32CubeIDE 工程的第一次板级冒烟。当前 `monitoring_node_f103ze` 工程已经生成并完成主机侧 Build；本文的运行步骤和退出门禁仍未代表目标板已经下载、复位、闪灯或 RTC 唤醒通过。

完整的界面配置、传感器外设、ADC DMA 和 FreeRTOS 步骤见 [STM32F103ZET6 STM32CubeIDE 完整配置教程](STM32F103ZET6_CubeIDE完整配置教程.md)。

## 1. 工程目标

M1 只证明以下链路：

`ST-Link 下载 -> 启动日志 -> LED/GPIO -> RTC 唤醒 -> Stop -> 唤醒后再次输出日志`

本阶段不接传感器、不启用 FFT、不创建完整五任务模型，也不测量整机功耗达标。

## 2. CubeMX 初始配置

| 配置项 | 初始值 | 备注 |
| --- | --- | --- |
| 芯片 | `STM32F103ZETx`，商业料号 `STM32F103ZET6` | 新建 ZET6 工程，不从其他封装的 `.ioc` 手工替换器件字段 |
| Debug | `JTAG (4 pins)` | 保留 PA13/JTMS、PA14/JTCK、PA15/JTDI、PB3/JTDO；PB4/NJTRST 释放 |
| 外部高速时钟 | HSE Crystal/Ceramic，8 MHz | 精英板 V2 资料与实物丝印需要一致 |
| 系统时钟 | PLL x9，预期 72 MHz | HSE 不为 8 MHz 时重新计算 |
| APB1 / APB2 | 36 MHz / 72 MHz | 以 Clock Configuration 校验 |
| USART1 | Asynchronous，115200，8 data，1 stop，无校验 | PA9 TX、PA10 RX |
| GPIOB5 | 推挽输出、初始 High、低速 | 板载 LED0/DS0，常见为低有效，首次下载验证极性 |
| GPIOD11 | 推挽输出、初始 Low、低速 | IO 表中完全独立，接逻辑分析仪作测试标记 |
| RTC / LSE | PC14/PC15 已选 LSE 外部晶体，RTC 尚未启用 | 资料表确认板载 32.768 kHz 晶振；后续启用 RTC 后必须实测起振和 Stop 唤醒 |
| FreeRTOS | M1 可暂不启用 | 先完成裸机冒烟，再在 M5 集成任务 |

## 3. M1 运行步骤

1. 新建 `STM32F103ZETx` 工程并选择商业料号 `STM32F103ZET6`，生成最小 HAL 工程。
2. 在 `main` 初始化后输出芯片型号、固件版本和复位原因。
3. 每 500 ms 翻转一次 PB5，确认 GPIO 和板载 LED0 极性。
4. 每次 RTC 唤醒时翻转 PD11，并通过 USART1 输出 `wake_source`、递增计数和运行状态。
5. 进入 Stop 前输出 `prepare_stop`，关闭不使用的外设中断。
6. 用 ST-Link 下载并复位，确认可以重复执行至少 20 次唤醒。
7. 用逻辑分析仪观察 PD11：应能区分运行、准备休眠和唤醒时刻。

## 4. ST-Link 接线

| ST-Link JTAG | ZET6 | 要求 |
| --- | --- | --- |
| TMS | PA13 / JTMS | 不接其他外设 |
| TCK | PA14 / JTCK | 不接其他外设 |
| TDI | PA15 / JTDI | 不接 ATK-MODULE LED |
| TDO | PB3 / JTDO | 不接 CAMERA/OLED WEN |
| NRST | NRST | 建议连接，便于复位和连接失败恢复 |
| 3.3 V 参考 | 目标板 3.3 V | 用于电平参考，不要误把 ST-Link 5 V 作为 MCU 电源 |
| GND | GND | 必须共地 |

若调试器只有 SWDIO/SWCLK 两线接口，应把 `SYS -> Debug` 改为 `Serial Wire`，并按 SWD 接线；不要保留 JTAG 模式却假定 TDI/TDO 已完成物理连接。

## 5. 退出门禁

- [ ] ST-Link 能识别目标芯片并下载固件。
- [ ] USART1 能稳定输出启动和 RTC 唤醒日志。
- [ ] PB5 LED0 极性已确认。
- [ ] PD11 波形能区分运行、休眠准备和唤醒。
- [ ] 连续 20 次 RTC 唤醒无死锁、无异常复位。
- [ ] 已保存工程配置、芯片 ID、下载日志和测试日期。

M1 通过后，才进入 M2 的 SPI 振动、I2C 温度和 ADC DMA 单设备验证。
